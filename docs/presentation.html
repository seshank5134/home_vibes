Problem Statement

Conventional food delivery depends on restaurant kitchens, which creates delay, quality loss, and poor operational visibility.

⏱️ High Delivery Latency

Delivery time is dominated by kitchen preparation backlogs, often 45–60 minutes end to end.

🍲 Quality Degradation

Cooked food loses freshness, heat, and texture during transit, and packaging cannot fully prevent it.

📡 Fragmented Operations

Customers, drivers, and admins lack one secure, real-time view of orders, stock, and vehicle location.

Core Problem Formulation

There is no scalable, secure, and real-time cloud platform that removes the kitchen bottleneck by delivering pre-portioned raw-ingredient kits with cooking scripts, while giving every stakeholder live visibility.

Speaker Notes: "In conventional delivery, up to 60% of the wait time happens in restaurant kitchens. Furthermore, cooked food degrades in transit, and systems suffer from fragmented operational views. HomeVibes addresses this directly."

Objectives of the Project

1 Design Decoupled 3-Tier Architecture

Customer web portal, driver mobile app, and admin console operating on one shared managed backend.

2 Use Cloud Service Models Effectively

Map the system cleanly to IaaS, PaaS, FaaS, and SaaS using Supabase as the managed platform.

3 Relational Cloud Database Modeling

ACID PostgreSQL 15 schema with constraints, foreign keys, order state history, and driver locations.

4 Enforce Security at the Data Layer

Supabase Auth with role-based access control and kernel-level Row Level Security (RLS) policies.

5 Real-Time Order & GPS Tracking

Push updates over persistent WebSockets (WAL Change Data Capture) instead of heavy client polling.

6 Automate Dispatch Serverless Logic

Server-side database and edge functions for claiming, pickup, delivery, and failure handling.

Speaker Notes: "We established six core objectives covering architecture, service models, relational modeling, data-layer security, real-time WebSockets, and serverless workflow automation."

Scope of the Project

In Scope

  • Admin Operations Console: Dashboard metrics, order queue, driver assignment, catalogue and stock toggling.

Related Work Focus Gap / Relevance to HomeVibes

System Architecture

Three decoupled clients talk to one managed Supabase backend over HTTPS and WebSockets.

Implementation: Database & Serverless Layer

🗄️ Relational Schema Visualizer

10 tables in Third Normal Form deployed on Supabase project home-vibes (main):

orders ──────< order_items (price-locked) │ ──────< order_status_history │ ──────< notifications │ drivers ─────< driver_locations (GPS)

Each order stores pickup and delivery coordinates, fee calculations, and an immutable timestamp per status change.

⚡ Database & Security-Definer Functions

Serverless functions running inside PostgreSQL with elevated security definer rights:

  • arrive_at_kitchen(p_order_id)
  • claim_order(p_order_id)
  • pickup_order(p_order_id)
  • start_delivery(p_order_id)
  • complete_delivery(p_order_id)
  • driver_toggle_online(p_is_online)
  • driver_update_location(p_lat, p_lng)
